# Global G01 — Master, engine and product identity

## Audit and implementation

The old Global panel exposed eight visualization bits. G01 retains that canonical mask and its existing document serialization/history. It adds product identity, Master, Voice/Performance, Engine, Appearance/Activity, Tuning/MIDI and Global Behavior, with Settings nested under Global. The persistent performance strip stays in place.

- **Master:** both controls write the existing host parameter `output.master`; one `FinalOutputStage` still applies gain after buses/FX. The shared `MasterOutputControl` renders compact and expanded views. Its mapping is unchanged: silence, normalized midpoint −12 dB, maximum +6 dB, unity at 5/6. Both meters read the same atomic final-output level/hold source. The expanded meter supplies L/R, a −60 to +6 dBFS scale, restrained green/yellow/red segments, peak hold and numerical held peaks. No new DSP metering, gain, modulation destination or audio-thread UI work.
- **Voice/performance:** canonical `PerformanceState` supplies Poly/Mono, Last/High/Low mono note priority, legato and 0–5 second glide. The engine has a fixed maximum of 16 MIDI voices; the page reports this instead of inventing a polyphony setting. Invalid performance edits are rejected before mutation.
- **Synchronization/history:** editor callbacks refresh both representations immediately after UI edits. Existing model refresh, content restore and timer paths hydrate the views after host automation, preset/project restore and history replay. The bottom strip now explicitly refreshes mode, priority, legato, glide and both bend endpoints from canonical state. Continuous Global controls use the existing document gesture/coalescing hooks; Master additionally retains its host gesture hooks.
- **Engine:** existing lock-free continuity/QoS telemetry provides actual prepared sample rate, last callback size/prepared maximum, active MIDI voices/fixed maximum, and smoothed callback wall-time/deadline percentage. The UI labels this Audio Load and describes its scope; it is not whole-system CPU. Before preparation/measurement, fields show unavailable states.
- **Activity:** all eight established categories remain: ENV, LFO, RANDOM, FUNCTION, CHAOS, DRIFT, SEQUENCER and OSC. Labels and ON/OFF controls are aligned in one row. Existing visualization semantics, persistence and Undo/Redo are unchanged.
- **Tuning/MIDI:** signed pitch-wheel endpoints use the existing −48..+48 semitone canonical fields, including same-sign endpoints. Center remains unshifted.
- **Settings:** an internal Global subview reuses shared `UserPreferences` for keyboard capture, the same preference exposed by the header menu. Its application scope is explained; it does not enter presets or document history. No new top-level tab or speculative settings system.
- **Panic:** the compact utility requests the existing atomic panic operation. Voices, effect tails and queued keyboard/ARP runtime clear on the audio owner thread without changing the patch. Because that callback returns before normal telemetry publication, it now also zeros the existing atomic voice/load-complexity counters immediately.
- **Identity:** existing Origami/Melogic wordmark, “SYNTHESIS, UNFOLDED.”, canonical CMake project version, configurable public build channel and target architecture. An always-run CMake dependency generates a short Git HEAD identifier, adds `-modified` for local Origami changes, or uses `source-archive` without Git. Only public strings are embedded; no checkout path, user name, remote, credentials or signing metadata. The canonical release remains **0.1.0**; the default public channel is **DEVELOPMENT**, not an invented beta release.

## Intentionally omitted

No backed user quality/oversampling controls exist. The fixed engine voice limit is read-only. Main Tuning/Transpose are modulation destinations with zero frame bases, not saved user tuning controls; there is no canonical A4 reference to expose. These controls are omitted. Settings contains the real existing application preference rather than placeholders for future subsystems. DAW restoration is tested through the processor's host state contract; this pass does not claim an interactive project round-trip in every DAW.
