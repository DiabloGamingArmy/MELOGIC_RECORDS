# L01.2 activation repair and simplification

1. **Baseline:** `b7913c55ca7a4883c793ee841bda45770624747a`, clean tree.
2. **Root cause:** `ActivationPanel::sync` used `signedIn && !busy && trimmedKey.isNotEmpty()` for enablement. The TextEditor callback already called `sync(false)` correctly, but signed-out account state made every nonempty key remain disabled. Logout was always added to the tree and only disabled when signed out. These were state semantics, not a failed text callback.
3. **Enablement:** empty/whitespace disabled; any trimmed nonempty input enabled when idle, including signed out. No format-as-validity check. The actual JUCE text notification updates controls without account timer sync. Return and click share one guarded action. Programmatic clearing explicitly recomputes state. During auth/restoration/redemption, duplicate actions and key edits are disabled.
4. **Continuation implemented:** signed-out Activate keeps one transient pending key in the initiating panel and starts the existing account sign-in service. Normal browser URL consumption/launch remains in the editor sync. Verified sign-in causes one `Service::redeem` submission; the pending string is consumed before enqueueing. An already-entitled account clears the key without redeeming it. Backend authorization remains authoritative.
5. **Signed-out UI:** fixed branding/tagline, one instruction, Sign In, OR, masked key field and Activate. No permanent signed-out status paragraphs.
6. **Logout:** removed from the child component tree while signed out. It is added for authenticated identity; Cancel Sign-In is added only while browser authentication is pending. Returning to signed out removes it again.
7. **Removed:** “Not signed in”, the repeated account-required paragraph, “OR / ENTER LICENSE KEY”, old verbose placeholder, profile hyperlink and footer separator. Tagline retained unchanged. Pending sign-in keeps the existing verification-code status, which is relevant security information.
8. **Open Melogic Account:** removed from the activation gate; `/profile` duplicated the canonical account path and did not advance activation. Existing Global account controls are retained.
9. **Branding:** original reference frame remains `getLocalBounds().withSizeKeepingCentre(min(500, width-40), 430)`. Original wordmark frame remains `(body.x+75, body.y, body.width-150, 80)` with centred image placement; tagline remains `body.y+85`, height 20. Only controls below this block moved. Wordmark/tagline pixels match the committed L01.1 baseline screenshots exactly at 960×600, 1440×900 and 1920×1200. Separate comparisons cover signed-out → authenticated/unlicensed and error presentation; child removal/insertion cannot shift the independent reference frame. No new BEFORE screenshot was attached to this turn; the committed activation screenshots and baseline source supply the comparison.
10. **Authenticated/unlicensed:** identity alone stays gated. A concise signed-in email appears; Recheck Access, Logout and redemption remain available. Routine unlicensed explanatory status is suppressed.
11. **Busy/errors:** SIGNING IN... / ACTIVATING... and concise progress, single submission guard, existing background transport, no network on message/audio thread. Classified invalid, expired, exhausted, unavailable/revoked and network failures stay safe and recoverable. No raw responses, tokens, key digests or server paths are displayed. Browser launch failure cancels the pending flow safely.
12. **Success:** existing trusted authorization response publishes the service atomic. Existing editor gate dismisses the overlay, restores workspace interaction, and existing audio gate opens. Editor sync now also clears activation state when hidden, preventing stale plaintext after successful authorization. Authorization loss still gates all editors and silences/resets audio through existing code.
13. **Lifecycle:** no worker callback captures UI. Pending continuation is owned by one panel; destruction discards it and cannot trigger later redemption. Cancellation/failed login do not redeem. Existing shared service ownership is unchanged. An already-enqueued redemption may complete in the shared worker after editor destruction; no UI access occurs. This does **not** fix or close the independent account-Service shutdown P0.
14. **Security/state:** masked entry preserved, only outer whitespace trimmed. No new persistence/logging APIs, no state/preset/history/network/audio changes. The transport's old minimum-length assumption was removed; empty/oversized transport inputs remain bounded, trusted backend validity/capacity/product checks remain unchanged. Existing complete DAW/preset serialization tests exclude identity/token, and a new assertion excludes the entered key. Production secrets, real keys and user Keychain data were never used in the UI tests or captures.
15. **Focused UI:** actual JUCE controls and real service worker with synthetic IO; text notification (not manual callback invocation) drives empty/whitespace/type/insert/delete tests without panel sync. Tests cover Return/click duplication, busy, exact trimmed pending input, auto-continuation, already entitled skip, cancellation, failed login, destroyed panel, errors/retry, plaintext cleanup, Logout child absence, and exact branding pixels. See `validation.txt` for final counts.
16. **Regressions:** account/auth coordinator, isolated Keychain, request-byte transport, cancellation/join, shared authorization, state/preset/history isolation, editor gate and allocation-free audio authorization tests retained. Full Release CTest results in `validation.txt`; no unrelated assertions removed. The old authenticated-unlicensed prose assertion now checks the deliberate absence of redundant prose while still requiring the gate to remain closed.
17. **Release wrappers:** fresh `origami/build-l012-release` configured with Release, `ORIGAMI_BUILD_TESTS=OFF`, `ORIGAMI_BUILD_PLUGIN=ON`, existing JUCE checkout. Clean initial Standalone/AU/VST3 builds plus final source refresh completed; generated binaries/build folders excluded from commit. These are development builds, not a notarized distribution release. No installed application/plugins were replaced and no production service was deployed.
18. **Limits:** canonical browser launch path retained; real personal sign-in and issued-key redemption across signed DAW hosts were not performed. Account-Service shutdown P0 remains independent. L02 offline licensing scope unchanged.
19. **Files:** `origami/plugin/ui/ActivationPanel.h`; `origami/plugin/PluginEditor.cpp`; `shared/melogic/account/FirebaseBackend.cpp`; `origami/tests/ActivationPanelTests.h`; `origami/tests/PluginTests.cpp`; `docs/origami-authorization.md`; this report, validation summary and synthetic screenshots under `origami/docs/qa/licensing-l012/`.
